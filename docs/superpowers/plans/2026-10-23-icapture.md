# iCapture 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `⌘⇧2`로 화면 영역을 캡처하면 AI 비전 모델(Claude / Nativ 로컬 LLM)이 텍스트를 정확히 옮겨 주고, 헷갈린 글자를 표시하며, 최근 10개 이력을 남기는 macOS 메뉴 막대 앱을 만든다.

**Architecture:** AppKit `AppDelegate` + `NSStatusItem` 위에 SwiftUI 창을 얹는다. 로직은 `Sources/iCapture/Core`(테스트 대상)에, 창·캡처·단축키 같은 앱 접착 코드는 `Sources/iCapture/App`에 둔다. 인식은 `RecognitionEngine` 프로토콜 뒤에 Claude(Messages API 직접 HTTP + SSE)와 Nativ(OpenAI 호환 SSE) 구현을 두고, `RecognitionSession`이 단계(읽기→수신→검사→완료)·경과 시간·취소·글자 표시를 관리한다.

**Tech Stack:** Swift 6.3 언어 모드, Xcode 27.1, XcodeGen, AppKit + SwiftUI, ScreenCaptureKit, Vision, Carbon `RegisterEventHotKey`, Security(키체인), ServiceManagement(로그인 시 실행), XCTest. 외부 패키지 없음.

**Spec:** `docs/superpowers/specs/2026-10-22-icapture-design.md`

## Global Constraints

- macOS 26.0 이상, Apple Silicon(`ARCHS: arm64`) 전용, Hardened Runtime on, 샌드박스 off.
- `SWIFT_VERSION: "6.3"` (Nativ와 동일). 엄격한 동시성 검사를 통과해야 한다. UI·세션 타입은 `@MainActor`.
- 앱 이름 `iCapture`, 번들 ID `dev.local.iCapture`, `LSUIElement = YES`(Dock 아이콘 없음).
- 서명: `Apple Development` 인증서, `DEVELOPMENT_TEAM = CJXSU64RQ8`, `CODE_SIGN_STYLE = Manual`. 화면 기록 권한이 다시 빌드해도 유지되려면 매번 같은 인증서로 서명해야 한다.
- 기본 캡처 단축키 `⌘⇧2`(Carbon keyCode 19 = `kVK_ANSI_2`, `cmdKey | shiftKey`). 전역 단축키는 이것 하나뿐이다.
- 이력: 최대 10개, FIFO, 최신이 위. 위치 `~/github/iCapture/hist/`. `hist/`는 `.gitignore`에 이미 있다.
- 비밀 정보는 키체인에만 저장한다. 서비스 `dev.local.iCapture`, 계정 `claude-api-key`, `nativ-api-key`.
- Claude: `POST https://api.anthropic.com/v1/messages`, 헤더 `x-api-key`, `anthropic-version: 2026-10-21`, `content-type: application/json`. 모델 ID는 정확히 `claude-sonnet-5-5`(기본) / `claude-haiku-5-5`. `temperature`·`top_p`·`top_k`는 보내지 않는다(이 API 버전에서는 400).
- Nativ: 기본 `http://127.0.0.1:8080`, `GET /v1/models`, `POST /v1/chat/completions`(`stream: true`), 이미지는 `image_url` 안에 `data:image/png;base64,…`. API 키가 있으면 `Authorization: Bearer <키>`.
- 복사는 서식 없는 일반 텍스트(`NSPasteboard.PasteboardType.string`)만 쓴다. 노랑·초록 표시는 화면 전용이고, 복사되는 텍스트에는 영향이 없다.
- 사용자에게 보이는 문구는 한국어로 쓴다(아래 각 태스크에 정확한 문구가 있으면 그대로 쓴다).

## Review Focus

1. **큰 캡처 이미지**: 5K 화면을 거의 통째로 고르면 PNG가 수 MB가 된다. API 이미지 한도를 넘지 않게 자동으로 줄여서 보내야 하고, 글자는 읽을 수 있어야 한다. → Task 3 `ImageEncoderTests.testDownscalesUntilUnderByteLimit`
2. **클릭만 하고 드래그 안 함**: 4pt보다 작은 영역은 캡처 취소로 본다. API 요청을 보내지 않는다. → Task 9 `CaptureGeometryTests.testTinySelectionIsRejected`
3. **스트리밍 중간에 네트워크 끊김이나 529 오류**: 받은 텍스트는 남기고, 오류 메시지를 띄우고, 편집할 수 있는 상태로 둔다. → Task 6 `RecognitionSessionTests.testErrorAfterDeltasKeepsPartialText`
4. **인식이 끝나기 전에 다시 캡처**: 이전 세션을 취소하고, 늦게 도착한 이전 글자가 새 결과에 섞이지 않아야 한다. → Task 6 `RecognitionSessionTests.testCancelledSessionIgnoresLateEvents`
5. **모델이 형식을 어김**: 종류 태그가 없거나, 결과를 ```로 감싸거나, 태그가 여러 청크로 쪼개져 도착하는 경우. 그래도 본문은 깨끗하게 남아야 한다. → Task 2 `KindTagParserTests`의 `testMissingTagFallsBackToOther`, `testStripsCodeFence`, `testTagSplitAcrossChunks`

### Task 2: 지시문과 종류 태그 파서

**Files:**
- Modify: `Sources/iCapture/Core/Recognition/RecognitionTypes.swift`
- Create: `Sources/iCapture/Core/Recognition/RecognitionPrompt.swift`, `Sources/iCapture/Core/Recognition/KindTagParser.swift`
- Test: `Tests/iCaptureTests/KindTagParserTests.swift`

**Interfaces:**
- Produces:
  - `extension TextKind { var badge: String }` → `"SQL"`, `"로그"`, `"표"`, `"기타"`
  - `enum RecognitionPrompt { static let system: String; static let userInstruction: String }`
  - `struct KindTagParser { init(); mutating func consume(_ delta: String) -> (kind: TextKind?, body: String); static func parseComplete(_ raw: String) -> (kind: TextKind, body: String) }`
    - `consume(_ delta:)`는 새로 도착한 조각 하나를 받아 내부 버퍼에 붙이고, **지금까지의 본문 전체**를 돌려준다. 첫 줄바꿈이 오기 전에는 `body`가 `""`이다(태그일 수 있어서 보류). 단, 누적된 글자가 `<<KIND:`로 시작할 수 없게 되는 순간 보류를 풀고 그대로 본문으로 낸다.
    - 태그를 확정하면 `kind`가 한 번만 non-nil로 나온다. 태그가 없으면 `.other`.
    - 코드 블록 처리: 본문의 첫 줄이 ```로 시작하면 그 줄을 숨긴다. `parseComplete`는 마지막 줄이 정확히 ``` 이면 그것도 지운다. 스트리밍 중에는 마지막 줄이 ```여도 그대로 두고, 완료 시점에 `parseComplete`로 정리한다.

`RecognitionPrompt.system` 문구(정확히 이대로):

```
You transcribe text from a screenshot exactly as it appears.

Output format:
- First line: exactly one tag describing the content: <<KIND:sql>>, <<KIND:log>>, <<KIND:table>>, or <<KIND:other>>.
- From the next line on: the transcription. Nothing else.

Rules:
- Copy every character exactly. Do not fix typos, grammar, SQL syntax, or formatting. If the source contains a mistake, keep it.
- Preserve line breaks, indentation, and spacing as seen.
- Do not add explanations, headings, or code fences.
- Transcribe Korean and other non-Latin text as-is.
- Tables and spreadsheet screenshots: output a Markdown table. For spreadsheets, omit the column letters (A, B, C, ...) and row numbers (1, 2, 3, ...); keep only cell contents. Keep empty cells empty.
- For look-alike characters (l/1/I/|, O/0, S/5, B/8, ,/.), decide from context: SQL keywords and identifiers, log formats, numbers.
- If text is cut off at the edge of the image, transcribe only what is visible.
```

`RecognitionPrompt.userInstruction` = `"Transcribe this screenshot."`

func testTagThenBody() {
    var p = KindTagParser()

func testStripsCodeFence() {

func testUnknownTagValueIsOther() {

### Task 3: SSE 파서, 이미지 인코더, Claude 엔진

**Files:**
- Modify: `Sources/iCapture/Core/Recognition/RecognitionTypes.swift`
- Create: `Sources/iCapture/Core/Recognition/SSEParser.swift`, `ImageEncoder.swift`, `ClaudeEngine.swift`
- Test: `Tests/iCaptureTests/SSEParserTests.swift`, `ImageEncoderTests.swift`, `ClaudeEngineTests.swift`, `Tests/iCaptureTests/Support/StubURLProtocol.swift`

**Interfaces:**
- Produces (in `RecognitionTypes.swift`):
  - `enum ClaudeModel: String, Codable, CaseIterable, Sendable { case sonnet = "claude-sonnet-5-5", haiku = "claude-haiku-5-5" }`
  - `enum EngineChoice: Codable, Hashable, Sendable { case claude(ClaudeModel); case nativ(modelID: String); var displayName: String }` → `"Claude Sonnet 5.5"`, `"Claude Haiku 5.5"`, `"Nativ: <modelID>"`
  - `enum RecognitionEvent: Equatable, Sendable { case textDelta(String); case verifying; case revisedText(String) }` — `textDelta`는 태그를 포함한 **원문 조각**이다. `verifying`과 `revisedText`(원문 전체)는 검사 단계가 있는 엔진만 보낸다. v1의 두 엔진은 보내지 않는다.
  - `protocol RecognitionEngine: Sendable { var choice: EngineChoice { get }; func recognize(png: Data) -> AsyncThrowingStream<RecognitionEvent, Error> }`
  - `enum RecognitionError: Error, Equatable, Sendable { case missingAPIKey; case http(status: Int, message: String); case refusal; case truncated; case nativUnreachable(url: String); case noNativModel; case network(String); var userMessage: String }`
- Produces: `struct SSEParser { mutating func feed(line: String) -> SSEEvent? }`, `struct SSEEvent: Equatable { var event: String?; var data: String }` — 빈 줄을 만나면 이벤트 하나를 낸다. `data:` 줄이 여러 개면 `\n`으로 잇고, `:`로 시작하는 주석 줄은 무시한다.
- Produces: `enum ImageEncoder { static func png(from image: CGImage, maxBytes: Int = 3_750_000, maxDimension: Int = 8000) throws -> Data }` — 크기 한도를 넘으면 0.8배씩 줄여 다시 인코딩한다(base64로 바꾸면 약 5MB).
- Produces: `struct ClaudeEngine: RecognitionEngine { init(model: ClaudeModel, apiKey: String?, session: URLSession = .shared); func makeRequest(png: Data) throws -> URLRequest }`

`userMessage` 문구:
- `missingAPIKey`: `"설정에서 Claude API 키를 입력해 주세요."`
- `http(401, _)`: `"Claude API 키가 올바르지 않아요. 설정에서 확인해 주세요."`, `http(429, _)` / `http(529, _)`: `"요청이 몰려 잠시 처리할 수 없어요. 잠시 후 다시 인식해 주세요."`, 그 밖의 `http`: `"인식 중 오류가 났어요 (\(status)): \(message)"`
- `refusal`: `"모델이 이 이미지의 처리를 거절했어요. 다른 엔진으로 다시 인식해 보세요."`
- `truncated`: `"결과가 너무 길어서 끝까지 받지 못했어요."`
- `nativUnreachable(url)`: `"Nativ 서버(\(url))에 연결할 수 없어요. Nativ에서 서버를 켜 주세요."`
- `noNativModel`: `"Nativ에 올라간 모델이 없어요. Nativ에서 이미지를 읽을 수 있는 모델을 올려 주세요."`
- `network(m)`: `"네트워크 오류: \(m)"`

Claude 요청 본문(`makeRequest`):

```json
{
  "model": "<model.rawValue>",
  "max_tokens": 16000,
  "stream": true,
  "system": "<RecognitionPrompt.system>",
  "messages": [{"role": "user", "content": [
    {"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": "<base64>"}},
    {"type": "text", "text": "<RecognitionPrompt.userInstruction>"}
  ]}],
  "thinking": {"type": "between_tools"}            // sonnet 전용
  "thinking": {"type": "disabled"}                 // haiku 전용
  "output_config": {"effort": "medium"},
  "fallbacks": "default"                           // sonnet 전용
}
```

- 헤더: `x-api-key`, `anthropic-version: 2026-10-21`, `content-type: application/json`. Sonnet이면 `anthropic-beta: server-side-fallback-2026-07-01`도 붙인다(모델이 거절할 때 서버가 다른 모델로 다시 돌려 주는 기능).
- 받아쓰기는 깊은 추론보다 지연 시간이 중요하다. 그래서 thinking은 끄고 effort는 `medium`으로 시작한다. 값은 `ClaudeEngine` 안의 `static let` 상수로 모아 두고, Task 12의 정확도 측정 결과를 보고 조정한다.
- 스트림 처리: `content_block_delta` 안의 `delta.type == "text_delta"`만 `.textDelta(text)`로 낸다. thinking 블록 같은 나머지 블록은 무시한다. `message_delta`의 `stop_reason`이 `refusal`이면 `RecognitionError.refusal`, `max_tokens`면 `.truncated`로 끝낸다. `event: error`는 `.http(status: 0, message: error.message)`로 끝낸다. - Test: `Tests/iCaptureTests/ConfusionMarkerTests.swift`, `TextDiffTests.swift`, `MarkRangesTests.swift`, `VisionOCRTests.swift`

**Interfaces:**
- Produces:
  - `protocol OCRProvider: Sendable { func recognizeText(png: Data) async throws -> String }`
  - `struct VisionOCR: OCRProvider` — `VNRecognizeTextRequest`, `.accurate`, `recognitionLanguages = ["ko-KR", "en-US"]`, `usesLanguageCorrection = false`(교정하면 비교 기준이 흐려진다). 관찰 결과는 위에서 아래(`boundingBox.midY` 내림차순), 같은 줄이면 왼쪽부터 정렬해 `\n`으로 잇는다.
  - `enum ConfusionMarker { static func marks(candidate: String, reference: String, kind: TextKind) -> [NSRange] }` — 반환 범위는 `candidate` 기준 UTF-16 `NSRange`.
  - `enum TextDiff { static func changedRanges(from old: String, to new: String) -> [NSRange] }` — `new`에서 바뀌거나 새로 생긴 글자의 범위(UTF-16). 공백은 비교에서 뺀다.
  - `enum MarkRanges { static func adjust(_ ranges: [NSRange], editedRange: NSRange, changeInLength: Int) -> [NSRange] }` — `editedRange`는 `NSTextStorage`가 알려 주는 편집 **후** 범위다. 편집 전 원래 범위(`location`, `length - changeInLength`)와 겹치는 표시는 버린다. 원래 범위의 길이가 0인 삽입은 표시 범위의 **안쪽**(시작보다 크고 끝보다 작은 위치)일 때만 겹친 것으로 본다. 그래서 표시된 글자 바로 옆에 타이핑해도 표시는 남는다. 원래 범위보다 뒤에 있는 표시는 `changeInLength`만큼 민다.

`ConfusionMarker` 알고리즘(이대로 구현):

```
1. 두 문자열을 (문자, candidate 쪽 UTF-16 오프셋) 배열로 바꾸며 공백류(스페이스·탭·줄바꿈)를 뺀다.
   kind == .table 이면 '|', '-', ':' 도 뺀다(Markdown 표 기호라서).
2. Array.difference(from:)으로 reference → candidate 차이를 구하고, 연속된 삭제/삽입을 하나의 "덩어리"로 묶는다.
3. 덩어리마다 candidate 쪽 글자 c[], reference 쪽 글자 r[]:
   - c가 비었으면 건너뛴다.
   - c.count > 3 또는 r.count > 3 이면 건너뛴다(OCR이 통째로 못 읽은 구간, 예: 한글).
   - c.count == r.count 이면 i마다 group(c[i]) != nil && group(c[i]) == group(r[i]) 일 때 c[i]를 표시한다.
   - 길이가 다르면 c 중에 group != nil 인 글자를 모두 표시한다.
4. 혼동 그룹: [l 1 I | i !], [O 0 o D Q], [S 5 s], [B 8], [Z 2 z], [G 6], [, .], [' ` ’ ‘], [" “ ”], [- – —]
   kind == .table 이면 첫 그룹에서 '|'를 뺀다.
5. 서로 붙어 있는 표시 범위는 하나로 합친다.
```
